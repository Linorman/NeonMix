## CPU 约束与有效测试区间

macOS 与 Ubuntu 采用 **1 Hz 整机总 CPU 采样**，记录逻辑核数、忙/闲占比与场景起止时间；单线程约 100% 不等于整机满载。实验前段采用连续约 10 秒低于 80% 的门槛，并在持续越限或接近 95% 时中止自有场景。用户随后明确“不用强行设置 CPU 上限”，最终四读者原强度复验已取消起步和中止百分比，保留自然负载测量。先前成功窗口的门槛没有触发，原数据保留，不把最后约束写成固定 80% 上限。

macOS 编译阶段曾观测整机满载，随后停止该次构建并以 Cargo/CMake 2 jobs 接续。Ubuntu 的 2/4 核 affinity 仅用于构建，LAN、音频矩阵与 GUI 由正常 `systemd --user` manager 启动，未继承构建限制。当前 manager 允许 `0-3` 四核；当时未保存每个 Hub/worker 的历史 affinity，因此这是启动流程核对，而非历史直接测量，见 [核对记录](evidence/platform-retest-20261003-022352/ubuntu/affinity-audit.json)。跨机测试时三端暂停本轮编译与其他压力；本轮没有停止用户原有程序以制造空闲条件。

## Ubuntu AirPlay：功能接通，定时质量失败

真实 Hub 的 ring PKCS#8 v2 身份在本机 OpenSSL 3.0.13 上读取正常，worker 能就绪、配对并释放 PCM。多入口、共享容量、定向控制、强杀/重连、身份保持、Mixer 偏好及管理均工作；总计 **36 次完整故障恢复**。四路含四并发读者完成 26,546 次状态查询，零查询错误。

这些功能断言没有验证全部输出采样连续性。进一步审计原始诊断发现，所有含 AirPlay 的稳态窗口 `timed_late_frames` 大幅增长：

| 组合 | 稳态 Mixer aggregate timed late 增量 |
|---|---:|
| 2 AirPlay | 186,065 |
| 4 AirPlay + 0 原生 | **999,658** |
| 2 AirPlay + 2 原生 | 218,262 |
| 3 AirPlay + 1 原生 | 343,779 |
| 1 AirPlay + 3 原生 | 108,109 |
| 0 AirPlay + 4 原生 | 0 |

四路 30 秒稳态由 23,743 增至 1,023,401，同时每路 ingress `late_packets` 与 underrun 增量为零。因此接入层零迟到不能覆盖 Mixer 已跳过采样。该指标是 Mixer 聚合量，不能在单路故障时直接归因于所有存活来源；本报告使用稳定播放窗口的 before/after 判定质量。

单路 PCM/ALAC 均完成同 session 暂停恢复和重复 SETUP、非零电平恢复，最终分别因 `retiming skipped output samples` 断言失败，失败时 timed late 为 **26,236 / 29,285**，worker late 为零。此时 CPU 未满载；不能把“恢复有声音”计作定时质量通过。

完整原始阶段、窗口计数、CPU 与清理见 [Ubuntu 平台报告](evidence/platform-retest-20261003-022352/ubuntu/README.md)、[运行汇总](evidence/platform-retest-20261003-022352/ubuntu/runtime-summary.json)。本轮未修复该定时问题。

## Windows：旧启动阻断消失，首轮异常保留

新 worker 经真实 Hub 私有 NamedPipe、完整身份读取、认证数字源、定时 Mixer 和 WASAPI 输出工作。原生安全 fixture 6 类通过：合法父进程/当前 SID/保护 DACL ready；广泛或未保护 DACL、非父 server PID、缺失 pipe、非法名称均拒绝且未泄露 fixture token。未将这些 fixture 夸大为跨账户 SID、PID 复用或独立饱和背压测试。

五种四路组合最终均有功能通过记录，共 **28 次完整恢复**。通过组合的采样稳态、故障和恢复窗口中，存活 lane 欠载与 late packet 增量为零；2+2 稳态前累计 timed late 1 帧、3+1 复验前累计 15 帧，稳态不再增加，不能声称从启动起绝对零。

首轮 3 AirPlay + 1 原生仍是产品链路失败：三个 worker 以 `decoder_queue` 退出，各路 late packet 193/194/196，Mixer timed late 7,292，尚未进入计划故障阶段。随后同条件一次复验完成 6 次恢复，CPU 平均 5.846%、峰值 18.711%。首次故障原因未定位，不以复验通过消除首败。
