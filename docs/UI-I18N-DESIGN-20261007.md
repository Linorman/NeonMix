# NeonMix UI 多语言模块设计

日期：2026-10-07。状态：原设计已完成首期开发；验收范围见开发计划及实施结果。首期语言：简体中文与英文。配套文档：[开发计划与 checklist](UI-I18N-DEVELOPMENT-PLAN-20261007.md)。

UI 增加 **Auto、简体中文、English** 三个选项，默认 Auto，按系统语言偏好选择实际显示语言。用户可以即时切换；页面、托盘、提示和可访问名称同步更新，正在运行的音频和未保存输入保持原状。后续增加语言通过语言登记、翻译资源和验收完成，不在业务代码中增加成组的语言判断。

实施结果见 [2026-10-07 实施报告](UI-I18N-IMPLEMENTATION-20261007.md)。下文保留原设计与选型说明，实际实现以当前源码、资源schema和已验证证据为准。

本设计沿用 Neon Console 的视觉、页面和交互体系。当前 [DESIGN.md](../DESIGN.md) 的“界面语言为简体中文”以及 [UX-CONTRACT.md](../UX-CONTRACT.md) 的偏好文件范围，应在功能实施时同步更新；本文不把设计提案记成已实现能力。

## 一 当前实现与改造范围

当前桌面使用 Rust、egui/eframe 0.31.1、AccessKit 和 tray-icon。它是原生桌面应用，本模块不引入浏览器、Web i18n provider 或新的 UI 框架。

| 现有位置 | 当前情况 | 改造要求 |
|---|---|---|
| `main.rs::Page`、`shell.rs`、`pages/*` | 页面名、按钮、提示直接包含中文 | 改为语义消息和资源查找 |
| `widgets.rs::field_sized/title_field` | 标签文本参与 `make_persistent_id` | 内部 ID 与显示标签分离 |
| `lanes.rs` | 角色、状态、网络状态保存为显示字符串 | 保存枚举或消息 ID，渲染时翻译 |
| `events.rs` | `RoomEvent.text` 保存中文句子，`Marks` 比较显示状态 | 事件保存语义和参数；差异比较不依赖语言 |
| `main.rs::Undo/message/shown_message` | 还原标题、状态反馈保存最终文字 | 改为可重复渲染的消息对象与稳定事件身份 |
| `palette.rs` | 分组、标题、关键词含固定文案 | 本地化标题与别名，以命令 ID 关联选择 |
| `tray.rs` | 托盘、macOS 菜单和 tooltip 在创建时固定中文 | 保存菜单项句柄，主线程更新文字 |
| `theme.rs` | 已有系统 CJK 字体查找及 `NEONMIX_CJK_FONT` | 保留并整理语言与内容的字体回退策略 |
| `UiPreferences` | 仅有 `reduce_motion`，setter 重建结构后写文件 | 统一偏好读写，增加语言字段且互不覆盖 |
| desktop-service `Reply/ProcessStatus` | 错误以 `Option<String>` 返回，可能已是中文 | 增加稳定错误码和受限参数，由 UI 翻译 |

首期覆盖七个页面、嵌入 Hub 的 AirPlay 面板、共享控件、确认框、状态条、快速操作、应用持有的原生菜单、tooltip、AccessKit 名称、输入校验、操作反馈、房间动态和相对时间。

以下内容保持其来源语义：用户房间名、来源别名、系统设备名、文件路径、UUID、端口、协议字段、机器日志键、JSON 枚举和单位符号。界面语言不重命名房间或设备，也不改变协议、权限、采样率和会话控制。

安装器、启动器失败弹窗及命令行帮助属于独立展示面。首期 UI 上线不以完整翻译这些展示面为前提；安装器不能代写桌面语言偏好覆盖 Auto。后续可共用术语表，但不要求 NSIS 或 C 启动器链接 Rust 翻译引擎。操作系统自身的 UAC、文件对话框和辅助技术语音可能遵循系统设置，应与 NeonMix 自有文案区分。

## 二 语言选项与默认规则

### 偏好和有效语言分离

采用两个状态，禁止把 Auto 简化成首次检测到的语言后写死：

| 状态 | 示例 | 含义 |
|---|---|---|
| `LanguagePreference` | `auto`、`zh-CN`、`en` | 用户选择，写入本机 UI 偏好 |
| `ResolvedLocale` | `zh-CN` 或 `en` | 本轮渲染使用的语言，由偏好解析得到 |

首期登记 `zh-CN` 为简体中文资源标识，`en` 为通用英文资源标识；地区英语先共用英文翻译，不宣称已提供不同地区专用词汇。`auto` 是产品选项，不是语言标签，也没有对应翻译资源目录。

默认行为明确如下：

1. 新安装、没有语言字段的旧偏好、没有偏好文件的既有安装，均采用 Auto。
2. Auto 按系统或应用的语言偏好列表顺序匹配受支持语言，不按 IP、时区、键盘布局或系统 ANSI 代码页推断语言。
3. 手动选择简体中文或英文后，该选择优先于系统语言，直到再次选择 Auto。
4. 系统没有提供可用语言，或整个语言偏好列表都不支持时，使用英文。
5. 系统语言变更只影响 Auto；在启动、窗口恢复/重新激活，以及打开语言设置时重新检测，不每帧查询系统。

旧版始终显示中文。按用户要求默认 Auto 后，没有保存明确语言的旧安装可能在英文系统上首次显示英文；这是本次默认规则的变化，应写入版本说明，不把旧安装一律迁移为手动中文。

### 匹配规则

先规范化语言、文字体系和地区，再匹配显式别名。逐项处理偏好列表，某一项不支持时继续下一项，只有列表穷尽才回退英文。

| 系统语言候选 | 首期匹配结果 |
|---|---|
| `zh-CN`、`zh-SG`、`zh-Hans`、`zh-Hans-*` | `zh-CN` |
| 无文字体系、无地区的 `zh` | 首期显式别名 `zh-CN` |
| `en`、`en-US`、`en-GB` 等英语候选 | `en` |
| `zh-Hant`、`zh-TW`、`zh-HK`、`zh-MO` | 首期不匹配；继续下一候选 |
| 其他未支持语言 | 继续下一候选 |
| 空列表、全部无效、仅 `C/POSIX` | `en` |

显式文字体系优先于地区推断：例如 `zh-Hant-CN` 不映射到简体，`zh-Hans-HK` 可以映射到简体。不得通过通用 `starts_with("zh")` 把繁体系统默认判为简体。未来增加繁体等资源后扩展登记及测试即可。语言扩展字段先通过规范的 locale 解析适配器处理，不把任意完整 BCP 47 字符串直接假设为 `unic-langid::LanguageIdentifier` 可接受的范围。

建议使用 `sys-locale` 获取偏好序列，封装在项目的 `SystemLocaleProvider` 后面。其 API 提供按优先级排列的 BCP 47 标签，无法取得时返回空序列；各平台实际读取来源仍须原生测试确认。[sys-locale get_locales](https://docs.rs/sys-locale/0.3.2/sys_locale/fn.get_locales.html)

例如 `[fr-FR, zh-Hans-CN, en-US]` 应选简体中文，不能看见首项不支持就立即选英文；`[zh-TW, en-GB]` 应选英文。

## 三 设置入口与切换体验

首期把语言选择放在“关于 → 显示 / About → Display”卡片内，与已有“减少动态效果”同属本机 UI 偏好，不增加第八个导航页。快速操作提供稳定的“语言设置 / Language settings”命令，打开关于页并聚焦选择框。

选择框标签固定显示 **语言 / Language**，列表中的语言用自称，避免切到不熟悉语言后找不到恢复入口。Auto 的说明随当前有效语言显示：

| 中文界面 | 英文界面 | 存储值 |
|---|---|---|
| Auto（跟随系统） | Auto (System) | `auto` |
| 简体中文 | 简体中文 | `zh-CN` |
| English | English | `en` |

Auto 下附一行“当前使用：简体中文 / Using: English”。确实因系统语言不支持而回退时，附简短说明；手动选项不展示系统跟随提示。不使用国旗代表语言。

选中后立即生效，不需要确认框、重启、重连后台或重新打开音频。切换在一次 UI 更新边界提交：先准备目标资源，再更新 `ResolvedLocale` 和 `locale_generation`，使本轮显示使用同一语言。弹出的语言列表选定后关闭，焦点回到同一个选择框。

必须保留当前页、选中来源、展开状态、搜索词、表单草稿、滚动位置、确认对象、还原截止时间和在途操作。布局因为文字长度发生合理重排，但不能重置业务状态或重新发送控制命令。输入法仍在组字时延后到合成结束处理自动语言变化；用户显式操作也不能提交或丢弃组字内容。

偏好保存失败时，当前窗口继续使用已选语言，显示本地化的“本次已生效，但未能保存，下次启动可能恢复”。记录待保存状态，提供重试；不得谎称持久化成功或因为失败重启音频。后台不可达时语言仍可切换。

系统变更检测只在上述边界生效，首期不承诺窗口持续聚焦时系统设置修改会立刻推送到应用。检测失败保留本次已经解析的语言；首次启动没有解析结果时才回退英文。

## 四 模块架构与依赖

推荐 **Fluent 资源 + Rust 类型化消息接口 + UI 持有的 Localizer**。Fluent 支持变量和语言相关的选择表达式；英文单复数可以放在资源内，不需要在每个页面写 `count == 1`。[Fluent selectors](https://projectfluent.org/fluent/guide/selectors.html)

```text
系统语言候选 ─┐
             ├─ LocaleResolver ─ ResolvedLocale ─ Localizer ─ egui 页面 / 原生菜单
UI 偏好 ─────┘                                  ↑
                                   语义消息 + 类型化参数
                                                ↑
                              UI 状态 / 房间事件 / IPC 错误码
```

拟新增 `crates/i18n`，包名 `neonmix-i18n`，提供资源解析、匹配、类型化消息、回退和显示格式。它只由桌面及检查工具使用，音频实时回调、Hub DSP 和 C++ worker 不依赖该模块。操作系统检测可放在桌面适配层；业务服务仅提供稳定错误数据。

| 职责 | 拟议 owner | 边界 |
|---|---|---|
| 受支持语言及别名 | `crates/i18n/locales/manifest.toml` | 唯一登记来源，包含 tag、自称、方向、状态 |
| 选择及回退 | `crates/i18n/src/locale.rs` | 纯函数，输入偏好和候选序列，输出有效语言及原因 |
| 文案和参数 | `locales/{en,zh-CN}/*.ftl`、`messages.toml` | 文案归资源，参数类型归 schema |
| 翻译执行 | `crates/i18n/src/localizer.rs` | 处理缺键、缺参数、资源错误与缓存 |
| 本机偏好 | 拟新增 `apps/desktop/src/preferences.rs` | 合并、迁移、原子保存语言与动效设置 |
| 系统语言及应用同步 | 拟新增 `apps/desktop/src/localization.rs` | 检测、主线程切换、失效缓存和通知菜单 |
| 原生菜单 | `apps/desktop/src/tray.rs` | 稳定菜单 ID，当前线程规则下更新文案 |
| 业务错误语义 | `crates/desktop-service` 的 Reply/ProcessStatus | 错误码及允许参数，不引入翻译引擎 |

初始依赖候选为 `fluent-bundle 0.16`、`fluent-syntax 0.12`、`unic-langid 0.9`、`sys-locale 0.3`；在实施 P1 阶段核实 Rust 1.95、目标平台、许可和 feature 组合后锁定精确解析结果到 Cargo.lock。这里是选型范围，不代表已添加依赖。`fluent-bundle` 提供资源、消息、参数和可收集错误的格式化接口，应用仍需自行封装回退及缓存。[fluent-bundle](https://docs.rs/fluent-bundle/0.16.0/fluent_bundle/)

不采用运行时在线翻译、随意加载外部语言包或多个全局可变 locale。每个 Desktop 持有一个 Localizer；UI 和原生菜单共用有效语言，后台线程返回语义数据，不从工作线程修改语言。

## 五 资源与类型化接口

建议目录如下，资源随二进制嵌入，离线运行不依赖安装路径中的可写翻译文件：

```text
crates/i18n/
  Cargo.toml
  build.rs
  messages.toml
  locales/manifest.toml
  locales/en/{common,shell,live,mixer,hub,sender,devices,diagnostics,about,errors,tray}.ftl
  locales/zh-CN/（相同模块）
  src/{lib,locale,localizer,format}.rs
  tests/（匹配、资源、参数、回退）
apps/desktop/src/{localization,preferences}.rs
tools/check_i18n.py
```

消息 ID 使用稳定语义和 Fluent 支持的连字符命名，如 `hub-start-sharing`、`error-output-unavailable`、`devices-offline-count`；不用中文原文、英文整句或运行时拼接字符串作 key。组件属性可使用 `.short`、`.tooltip`、`.a11y`，同一操作保持术语一致，允许短显示名与完整可访问名称不同。

`messages.toml` 定义消息 ID、参数名、参数类型及必要属性，作为类型化接口的唯一 schema。构建工具据此生成 Rust `Message` 枚举/构造方法，并检查两种语言的 FTL。FTL 保有自然语言表达权，不生成另一份手写枚举与 schema 重复维护。

拟议接口示意，以下并非现有 API：

```rust
let label = i18n.render(&Message::HubStartSharing);
let count = i18n.render(&Message::DevicesOfflineCount { count: 2 });
widgets::field(ui, "hub-room-name", &i18n.render(&Message::HubRoomName), draft, false);
```

对无参静态文案可以缓存；动态文案在显示层格式化。消息对象不实现真实时间计时，不缓存失效的权限或设备状态。

FTL 示例：

```ftl
# en/devices.ftl
devices-offline-count =
    { $count ->
        [one] { $count } paired device is offline
       *[other] { $count } paired devices are offline
    }

# zh-CN/devices.ftl
devices-offline-count = { $count } 台已配对设备离线
```

参数的 schema 均为非负整数 `count`；译文的复数分支不要求相同，参数含义和类型必须一致。校验工具解析 AST、检查引用和参数，不用正则表达式代替 FTL 语法解析。

必须翻译完整句子，如“正在连接 {name}”，不能拼接“正在”+动作+设备名。用户内容作为字面参数插入，不能被解析为新的 FTL、消息 ID 或格式字符串。方向隔离符在混合方向内容中有实际用途；保留 Fluent 的隔离机制，显示和辅助功能测试覆盖其行为；复制设备 ID、路径或邀请时取原始字段，不从已经格式化的句子反向提取。

英文作为完整的最终回退资源。资源加载和渲染顺序是“当前语言对应消息 → 英文对应消息 → 内置通用英文失败提示”；生产 UI 不裸露 key、`{ $name }` 或 panic。开发环境可额外显示缺失 key 便于定位。正式发布要求中英文 key、必要属性及参数契约全部完整，不能用回退掩盖漏译。

## 六 状态和错误的语言边界

### 动态消息保存语义

`RoomEvent` 改为 `at + kind + args + tone`，其中名称保留事件发生时的显示值，语言在渲染时决定。已发生事件在切换语言后重新显示，但时间、事件数量和对象不变。`Marks` 比较业务状态枚举；否则把状态字符串翻译成英文可能被误判为新的播放状态变化。

`Undo` 保留操作种类、对象名称及逆操作，不保存最终中文标题。切换语言不能重置 8 秒窗口。底栏消息、错误去重和动画键应使用消息身份、请求 ID、语义参数，不能因为翻译文字变化重新触发通知或重复报错。

`Lane` 的 `status/role/network` 改为语义类型，由共用显示函数提供文本与 tone，供现场、Mixer、Sender、诊断复用。角色、滤镜选项及命令执行分支不得再比较“正在播放”“管理员”等显示字符串。

### 后台错误使用稳定代码

仅替换桌面文案无法覆盖 backend 已经生成的中文错误。建议在 Reply 及持久于进程状态中的错误结构增加可选结构化 fault：

```json
{
  "ok": false,
  "data": null,
  "error": "兼容旧客户端的消息",
  "fault": {
    "code": "hub_port_in_use",
    "params": { "port": 7443 }
  }
}
```

新 UI 优先读取 `fault.code`，按白名单校验参数并映射到类型化 Message。后台不接收 UI locale，不以用户当前语言写协议状态。现有 `revision_conflict`、`permission_denied` 等代码继续沿用，新增加端口占用、偏好保存失败、生命周期及网络配置错误时同步登记语义。

保留 `error` 兼容旧客户端，并为新字段提供反序列化默认值。是否保持 IPC version 1 必须通过旧/新客户端和后台四种组合验证，不能仅因增加的是可选字段就宣称兼容。新 UI 遇到旧后台已知机器码时仍能映射；遇到未知文本时显示当前语言的通用错误及后续操作，技术详情单独受控展示，不对中文错误句子进行匹配翻译。

错误参数只包含该消息允许的公开数据，如端口、数量、公开状态。身份凭证、PIN、token、PEM 及任意 stderr 不进入翻译参数。机器日志和脱敏诊断继续遵守原白名单，新增 fault 不意味着可直接序列化进导出。

## 七 内部 ID 与布局

所有持久交互状态都使用独立稳定 ID：字段、ComboBox、ScrollArea、折叠面板、modal、快速操作选项、颜色动画、tooltip owner、AccessKit 节点与截图定位。数据对象使用稳定 UUID、stream/session ID 组成 ID；同页重复控件以父 scope 与对象 ID 消除冲突。

例如 `field(ui, stable_id, label, ...)` 替代由 label 推导 ID，`Page` 保留现有枚举，页面标题由消息生成。当前 DESIGN.md 记录的“胶囊按文字、卡片按标题”动画身份也需要在实施中改为显式语义 ID；只修字段仍会留下切换时的动画重置。

继续遵守 600×440 最小窗口、固定 36px 状态条、单正文滚动区、窄窗 Mixer 行式降级，以及 32px 常规按钮高度。英文更长时测量实际排版宽度：按钮整行换行或采用审核过的短标签，不能缩小到不可读字号。状态条视觉省略但保留完整可访问值；重要消息还应支持键盘访问的详情，不只提供鼠标 hover。

侧栏的宽度和 Mixer 138px 通道布局阈值不得假设中文和英文等宽。优先测量当前文案并使用已有响应式降级；确需调整共用阈值时，同时更新 DESIGN.md、共享组件和双语截图。确认框在英文下也须保持取消及危险动作完整可见。

预留 `TextDirection` 元数据，首期只发布 LTR 语言。未来 RTL 语言必须验证 egui 文本塑形、双向排版、输入、焦点顺序和布局镜像能力；新增资源文件不代表获得 RTL 支持。音频流向图、推子增益轴、技术 ID 的方向不能机械镜像。

## 八 字体与显示格式

首期保持现有字体风格和字号体系，给英文保留可读的 Latin 字体回退，同时继续加载 CJK 字形，因为英文 UI 也可能显示中文房间和设备名称。不得在切到英文时简单移除中文字体。

`theme.rs` 当前使用进程生命周期内的字体数据，切换语言不能每次重新读取并泄漏一份大字体。字体按文件/face 缓存，切换仅调整已加载字体策略；缺失字体时给出可读的恢复入口和英文兜底。三端正式分发需明确 CJK 字体来源：系统字体可复用，缺失平台提供经许可审核的字体包或明确安装依赖，不把开发用环境变量当作最终安装体验。

显示格式集中在 `LocaleFormat`，包括整数、有限精度小数、百分比、相对时间和普通日期。首期中文/英文共用明确的点号小数、计量精度及 SI 单位策略；英文相对时间按单复数处理。后续需要不同数字分隔、地区日期和排序规则时扩展格式适配器，不在页面中硬写。

机器 JSON、可复制 ID、版本号、端口和协议时间戳保持固定格式；`dB`、`dBFS`、`Hz`、`kHz`、`ms`、`ppm` 不翻译。语言不改变时区：相对时间仍由 `Instant` 计算，绝对时间显示若出现则沿用明确的本地时区策略。Fluent 消息引擎并不等于已经接入完整地区日期/数字格式服务，实施时验证实际能力，不根据 FTL 文档中的 `NUMBER/DATETIME` 示例推断 Rust 默认实现完整支持。

用户可编辑数字字段若未来支持逗号小数，须同时规定输入解析，不能只改变显示。首期音量推子和技术读数保持现有数值语义。

## 九 快速操作与原生菜单

快速操作条目以 `Cmd` 和对象 ID 标识，不用翻译标题定位执行对象。标题、分组和搜索别名随语言切换；保留 `Mixer/Hub/Sender/AirPlay/Solo` 等稳定技术词作为跨语言搜索入口。首期保持中文和英文常用别名均可命中，新增语言可增加本地别名。

切换后保留查询；重建结果时优先保留同一命令 ID，若已不可见则移到首个有效结果。输入法组字期间不因 Enter 执行操作。设备搜索继续匹配原始名称及用户别名，不翻译和改写设备数据，也不因语言切换重新排序正在操作的通道。

托盘和 macOS 应用菜单通过保存的 MenuItem 句柄修改文字，菜单 ID、快捷键和回调保持。更新发生在平台允许的主线程，不重复注册全局 MenuEvent handler，不重建托盘图标来刷新语言。原生菜单打开时可在关闭后安全更新，但下一次打开必须显示新语言。系统不提供 tooltip 的平台不能据此判应用漏译。

窗口标题继续使用产品名 `NeonMix`。当前 Windows 单实例唤醒按该标题查找窗口，语言切换不能破坏它；如未来引入带本地化页名的标题，应先改为稳定窗口识别。

## 十 偏好存储和迁移

继续使用当前 state-dir 内的 `ui-preferences.json`，作用域为本机该桌面配置，不进入 Hub profile，不发送给其他控制端。

```json
{
  "version": 2,
  "reduce_motion": false,
  "language": "auto"
}
```

兼容旧文件 `{"reduce_motion":true}`，保留动效选择并为语言补 Auto。所有 setter 通过同一个 Preferences owner 更新部分字段；切动效不能清掉语言，切语言不能清掉动效。使用同目录临时文件及平台合适的原子替换，不裸写目标文件；遵守现有私有目录及文件校验约束。

缺失文件使用默认值。损坏文件限制读取大小并显示可操作错误，不在自动启动时覆盖原文件；明确保存时再按备份/恢复策略处理。合法但当前未支持的语言值保留原值，运行期回退英文并提示；不要自动改写为英文造成以后无法恢复。未知更高 schema 版本不盲目覆盖，允许本次窗口临时选择并说明未保存。

同一 state-dir 若平台允许多个窗口进程，写入使用锁和读改写，避免两边互相覆盖。预览及测试模式使用注入偏好和系统语言提供者，不读取或写入真实用户设置。旧版本回退可能丢掉新增字段，属于 UI 偏好兼容限制，不影响身份、配对或音频资料。

## 十一 术语与翻译维护

| 简体中文 | English | 约束 |
|---|---|---|
| 现场 | Live | 主视图导航 |
| Mixer | Mixer | 保留专业名称 |
| Hub 设置 | Hub settings | 房间设置入口 |
| Sender | Sender | 原生发送入口 |
| 设备管理 | Devices | 导航用短标签 |
| 诊断 | Diagnostics | 不能译成系统调试器 |
| 关于 | About | 含本机显示设置 |
| 开始共享 / 停止共享 | Start sharing / Stop sharing | 与开始/停止发送区分 |
| 开始发送 / 停止发送 | Start sending / Stop sending | 不等于退出后台 |
| 还原混音更改 | Undo mix change | 与撤销配对区分 |
| 撤销配对 | Revoke pairing | 权限动作，保留后果说明 |
| 隐藏窗口 | Hide window | 不结束音频 |
| 退出后台 | Quit background audio | 必须说明结束本实例音频 |
| 未取得 | Unavailable | 不伪装成零值 |
| Mixer 队列估计 | Estimated Mixer queue | 不宣称实测端到端延迟 |

完整术语表和每条消息的上下文由资源注释维护：出现位置、动作后果、参数含义、短标签要求和可访问名称。不同语境不因原文相同就强行复用同一个 key。翻译审校重点覆盖停止共享/停止发送/隐藏/退出，以及断开/撤销/还原等容易混淆的操作。

新增语言先登记为 draft；翻译、参数检查、布局、字体、输入和母语审校通过后才设为 shipped，并进入选择框及 Auto 匹配。只完成部分翻译的语言不出现在正式选项中。

## 十二 性能与验收边界

资源在启动或首次使用时解析一次，无每帧文件 I/O；页面只读取 UI 持有的翻译状态，音频实时线程零参与。静态缓存按 locale generation 失效，动态文案按实际参数更新，不创建无界缓存。原生菜单只在有效语言变化时刷新。

正式验收须覆盖 Auto 默认及系统候选回退、双语所有页面、原生菜单、错误路径、字体缺失、600×440、输入法、辅助功能，以及播放期间多次切换。新译文长度通过伪本地化扩展测试，语法及参数由 CI 校验；具体 checklist、命令和退出标准见 [开发计划](UI-I18N-DEVELOPMENT-PLAN-20261007.md)。

跨平台运行、翻译质量和 RTL 能力不能从资源完整、编译通过或单个平台截图推断。该模块实施时还需与 [Windows AirPlay 改进方案](WINDOWS-AIRPLAY-RELIABILITY-PLAN-20261007.md) 的结构化错误和生命周期变更协调，保持 UI 语言变化与音频生命周期独立。
