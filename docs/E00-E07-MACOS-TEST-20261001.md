# macOS E00–E07 测试报告（2026-10-01）

后续修复：本文四项确认问题已完成修复和本机复验，见[修复与复验记录](E00-E07-MACOS-FIXES-20261001.md)。本文保留修复前的测试结论与原始证据。

本机主要音频与后台功能通过，但不能判定 E00–E07 全部验收通过：严格 Clippy 失败，Sender 发现页存在返回值结构错误，最小窗口导航重叠，输入框缺少辅助功能名称。此次只测试和记录结果，没有修改产品实现。

依据 `02_NeonMix_完整开发计划.md` §4.1–4.7、§5–6，`01_NeonMix_设计方案与技术选型.md` §5–8，以及 `docs/STATUS.md`、现有接口合约和探针。环境为 macOS 27.0 / Apple Silicon arm64、Rust 1.95.0、SDK 27.0、GStreamer 1.28.7；测试设备包括内置扬声器、BlackHole 2ch 和已安装的 NeonMix HAL。

## 已确认的问题

1. **P1：Sender 发现页丢弃真实发现结果。**点击“发现局域网房间”后，页面仍显示“尚未发现房间”。同一状态下直接执行 IPC `discover`，返回 7 条事件，最后一条 `discovery_complete` 包含 1 个房间。后台 `run` 把多行 JSON 返回为事件数组，而 `Desktop` 的 `Request::Discover` 分支直接对顶层值调用 `get("candidates")`，结果为空。对应实现为 `crates/desktop-service/src/daemon.rs` 的 `run/hub_command` 和 `apps/desktop/src/main.rs` 的发现结果处理分支。应统一发现返回值合约，并用真实多事件返回值补充 UI/IPC 回归。[结构对照](evidence/macos-e00-e07-20261001-132347/discovery-ui-contract-mismatch.json)、[IPC 原始返回与界面树](evidence/macos-e00-e07-20261001-132347/sender-ui-controls/result.json)、[发现页截图](evidence/macos-e00-e07-20261001-132347/sender-ui-popup-closed/discovery-no-room.png)。

2. **P2：600×440 最小内容窗口顶部导航和状态重叠。**Mixer、设备管理及诊断等页面的顶部状态覆盖导航文字，右侧内容被裁切。截图来自真实 macOS 窗口，使用双路测试记录的公开状态作预览；预览横幅不影响这一顶部问题。界面声明支持的最小尺寸没有满足布局要求。[Mixer 截图](evidence/macos-e00-e07-20261001-132347/ui-visual/mixer-600.png)、[诊断截图](evidence/macos-e00-e07-20261001-132347/ui-visual/diagnostics-600.png)。

3. **P2：公共文本输入框缺少 AX 可访问名称。**“房间名称”“搜索设备”“设备名称”“虚拟输出名称”等在辅助功能树中只有 `text field 1/2/3`，无法按字段名称定位。`widgets::field` 渲染独立文本标签，但没有把标签关联到 `TextEdit`。原生既有探针因此在房间名称字段处失败；后续按控件序号继续操作并不意味着此缺陷已修复。[首次失败](evidence/macos-e00-e07-20261001-132347/native-ui/native-ui-macos.json)、[五页 AX 树与截图](evidence/macos-e00-e07-20261001-132347/ui-visual/result.json)。

4. **工程检查失败：Clippy `-D warnings` 报告 37 项错误。**包括 `animation.rs`、`theme.rs`、`widgets.rs` 中的未使用函数/常量及桌面代码可折叠的条件分支。`tools/check.py` 按设计在此提前停止；随后单独运行 workspace 测试和 release 构建，二者通过。构建仍有警告，不能引用历史“无警告通过”的记录作为本轮结论。[完整日志](evidence/macos-e00-e07-20261001-132347/clippy.log)。

## UI 测试的通过项与限制

五页分别在默认 1100×760 和最小 600×440 内容尺寸打开，保存 10 张截图及 AX 树；Retina 图片像素尺寸是逻辑窗口的两倍。中文文本粘贴、剪贴板恢复、切页保留房间草稿、Space 激活导航、设备搜索无结果与清除通过。截图生成和基本交互成功与视觉验收是否通过分别记录。[结果](evidence/macos-e00-e07-20261001-132347/ui-visual/result.json)。

真实 GUI 创建房间和开始共享、Cmd+W 隐藏、托盘恢复、GUI SIGKILL 后 Hub PID/输出帧继续及重新打开恢复状态通过。一次补测完成总静音/恢复和脱敏导出；重复的 AX 自动化存在点击与权威状态未一致、屏幕外控件和查询超时，完整顺序脚本没有全通过。这些失败保留，不能直接推断为媒体控制实现缺陷。[包含已通过场景的原始记录](evidence/macos-e00-e07-20261001-132347/ui-workflow-final/result.json)。

退出确认单独完成：Escape 取消后 Hub 继续；点击确认弹窗中最后一个“退出后台”按钮，UI 正常退出、IPC socket 移除、Hub PID 结束。前面的整流程脚本曾定位到同名底栏按钮，未把这一定位错误当作产品退出故障。[专项结果](evidence/macos-e00-e07-20261001-132347/quit-ui-result.json)。

Sender GUI 的中文设备名及邀请粘贴配对、BlackHole 提供者选择、输出绑定添加、改名保持 ID、开始/停止发送保留 Hub、禁用/启用不自动发送通过。发现显示失败仍然保留；设备授权和删除确认的完整 GUI 顺序流程因后续自动化超时未完成，其后台接口已有 12 组双路探针通过。邀请是密码字段，AX 返回掩码；首次把掩码与原文比较的失败属于探针问题，后续以实际配对成功验证粘贴。[Sender UI 结果](evidence/macos-e00-e07-20261001-132347/sender-ui-popup-closed/result.json)、[运行截图](evidence/macos-e00-e07-20261001-132347/sender-ui-popup-closed/sender-running.png)、[后台双路结果](evidence/macos-e00-e07-20261001-132347/mixer/mixer-macos.json)。

完整 VoiceOver 听读、真实中文输入法合成、不同显示器/DPI 和 200% 缩放矩阵没有执行。物理设备拔插、睡眠、需管理员授权的 Core Audio 服务重启、干净机器安装/升级/卸载、签名公证、跨平台实机和跨机长期测试也没有在本轮执行；历史证据不计为此次复测通过。

## 版本、产物与清理

测试期间有并行 AirPlay 开发修改源码和重建共享二进制，新增 crate 暂缺 manifest 时原始漂移命令无法启动。后续保存项目内源码/二进制快照；运行用 UI SHA-256 为 `1e142aa0a8f66120e5f8121365f8a9b2fd6bbde316c29be167377b4292e1f5c3`，其他制品哈希见主结果。源码快照中的 Mixer 文件与初次构建哈希不同，3 项漂移补测只对应其明确记录的快照，不能宣称来自完全相同的源码版本。[快照说明](evidence/macos-e00-e07-20261001-132347/source-snapshot.json)、[漂移补测日志](evidence/macos-e00-e07-20261001-132347/drift-snapshot.log)。
