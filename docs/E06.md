# E06 虚拟输出：实现与验收

macOS 自研 HAL 已实际安装、发布系统设备，并通过普通应用、数字桥接、名称绑定及服务重启验证。用户追加授权的 Ubuntu ARM64 桌面也已通过虚拟输出、音量、绑定、权限与服务恢复检查。Windows 仍只有源码和交叉检查；三端 E06 完整门槛保持未完成。

## macOS 自研虚拟输出

Rust AudioServerPlugIn 提供固定 UID `com.neonmix.audio.virtual-output`，48 kHz stereo float32；Core Audio 将普通应用的其他格式转换到设备格式。设备声明、可选性、可见性、时钟域、输入/输出流、标准主音量/Mute、格式范围、UID 翻译和完整接口表已接通。用户确认系统设置 → 声音 → 输出列表可见 NeonMix，系统 API 枚举与实际默认输出选路另有运行证据。

```sh
tools/dev target/release/neonmix-hub virtual-output --provider neonmix
tools/dev target/release/neonmix-hub send \
  --credential <sender-credential.json> --hub <https://hub-address> \
  --virtual-output --virtual-output-provider neonmix --seconds 60
```

插件仅做设备、时钟与有界样本交换，不做网络、编码或用户配置文件 I/O。混音后的 WriteMix 经过一次主增益/Mute，写入 48000 帧时间标签缓冲；ReadInput 读取同时间坐标，未写、覆盖及新时间线填零。立体声打包为原子 UInt64，时间标签按 SeqCst 发布，避免并发环绕撕裂。数据回调共享 Sync 引用，不制造可变别名；控制线程关闭入口并排空已有回调，音频线程不等 mutex。时钟以有界版本快照读取 anchor/seed。

首个客户端启动时建立时间线，最后一个停止或异常移除时结束；其他活动客户端保持时钟/音频。活动客户端最多 128；回调帧数和指针长度有上限与检查。数据/时钟实际 C 接口 1000 周期分配审计为零分配、零重分配、零释放；这不等同于系统硬实时保证。

## macOS 真实证据

| 场景 | 结果 |
|---|---|
| 实际系统加载与设备选择 | arm64 bundle 安装到 HAL 目录；Core Audio 独立驱动宿主发布唯一 UID，输入/输出实际 48k stereo f32 |
| 普通应用与格式转换 | 系统默认输出选到 NeonMix；afplay 播放 44.1k PCM16 文件，实际 48k 采集读回正确 437 Hz |
| 双应用 | 两个 afplay 流混音，RMS 比单路约 √2 |
| 主音量/Mute | 标量 0.5 的实际振幅比 0.5000000000000553；Mute 为数字静音，恢复完整，只应用一次 |
| 无源、停源 | 回调持续，样本为零，无旧音频 |
| 加密 Sender/Hub | 真实自研输入 → Opus/SRTP → 原生 Hub，通过认证、非零 PCM 与时间戳检查 |
| 明确停止与重新发送 | 停止 Sender 不删除设备，普通应用/独立采集继续；新发送使用新会话和媒体上下文 |
| 固定设备率 | 原生 44.1k 设置被拒绝，保持 48k；不宣称插件支持任意原生采样率 |
| 名称与绑定 | 系统 Name 读回与保存标签一致，改名不改变 UID/output_id/hub_id，不中断真实 PCM |
| 撤销与身份 | disable/enable、remove 停止旧 Sender、不自动恢复；地址变化保留绑定，不同 Hub 在媒体前拒绝 |
| 服务重启 | Core Audio PID 76818→86446；旧输入/输出明确故障退出，同 UID 重新枚举，新的非零数字桥接/原生时钟通过，错误和回调超预算为 0 |
| 设置与临时文件 | 探针恢复默认输出、名称、音量、Mute 与采样率，删除临时 WAV/凭证；没有持久化采集 PCM |

## 名称、授权与历史修正

共享绑定 Store、revision 冲突、本地授权代际及独立撤销守卫见 [输出绑定合约](OUTPUT-BINDING-CONTRACT.md)。绑定 Sender 明确选择原生 UID，缺少/重复身份或不匹配 Hub 都失败，不切默认麦克风、不自动恢复广播。

标准 Name (`lnam`) 对 Core Audio 客户端只读。自研插件通过 `cust` 声明 `nmna` 的 CFString 数据类型与无 qualifier，自定义 setter 验证字符串后通知标准 Name/自定义属性；`output sync-name` 和绑定 Sender 启动使用此路径。真实跨进程读回通过。第三方 BlackHole 不改厂商名称。

首次系统加载未发布设备；补齐标准默认设备可选性、hidden、时钟域及物理格式范围后，实际系统注册与桥接通过。原始日志在 `artifacts/e06-hal-load-specific.log`、`artifacts/e06-hal-service-helper.log`。AMFI 的 ad-hoc/unknown-chain 提示不能单独证明加载失败，后续实际设备证明本机开发签名可加载。

此前离线允许写标准 Name，但实际系统返回 `nope`；修正为自定义 setter 后通过。历史失败在 `artifacts/e06-binding/20260930-175759`。服务恢复首轮操作者未在 60 秒内重启，记为超时失败；扩大手动窗口后实际进程更换与重开通过，失败没有改写为成功。

## Linux 本地 owner

独立 `neonmix-audio virtual-output` 持有 `pipewire:neonmix.sink.default`，网络 Sender 只读，停止/断网不删除节点。每 UID abstract socket 和私有目录/文件锁防重复；未退出的后台 worker 阻止第二次创建。服务器/节点故障后 250ms..5s 退避，稳定十秒才重置。

本地 PipeWire adapter/impl-node 导出到用户会话，控制循环原地修改 description/nick；`node.name` 不变。名称 IPC 核对 SO_PEERCRED，请求/队列有界，不进入音频回调；`--output-binding` 恢复名称，首次没有绑定仍能启动，支持先创建节点再绑定。用户级 service 模板在 `drivers/linux/`，尚未安装/启用。

```sh
# 在已登录的非 root PipeWire 用户会话运行。
neonmix-audio virtual-output --state-directory <private-runtime-directory> --output-binding <binding-directory>
```

Ubuntu 24.04.3 ARM64 / PipeWire 1.0.5 / WirePlumber 0.4.17 实测通过：操作者确认系统输出列表可见，普通应用格式转换、双应用混音、原生 0.5 增益/Mute/无源静音、加密 Sender、原地名称及绑定撤销、PipeWire/WirePlumber 重启和节点移除后的唯一逻辑身份/数字重开。修复 export readiness 事件顺序及会话管理器恢复路径；实际恢复过程中运行时 global ID 可以变化，固定 node.name 不变。正常用户 manager 启动及 NoNewPrivileges 基线通过；root 和跨 UID 控制被拒绝。原生 release、Clippy 与 7 项针对性测试通过。完整范围、失败与清理状态见 [Ubuntu E06](UBUNTU-ARM64-E06.md)。注销、整机睡眠及分发矩阵尚未执行。

## Windows render 原型

单 render WaveRT 源码来自锁定微软简化 SysVAD/MS-PL，去掉采集/测试音/PCM 落盘与伪硬件音量，声明软件音量；DMA 256KiB、通知最多两项，先停 timer 再释放。INF 固定 owner 标记用于 Rust 自有 eRender 端点选择，拒绝物理端点/相似名称，多个自有端点要求明确选择。`output sync-name` 用公开 property store、Commit 与读回，写入需管理员权限；普通 Sender 不提升、不切默认输出。

十个 C++ 单元在 macOS 以项目内 WDK/SDK 10.0.26100.6584 编译并链接 unsigned x64 PE，NX/ASLR/CFG 检查通过；真实 MSVC、签名、音频、HVCI、Verifier/HLK 和生命周期仍未验收。[驱动合约](../drivers/windows/wavert/DRIVER-CONTRACT.md)保留来源、上限及门槛。
