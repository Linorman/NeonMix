# NeonMix UI 多语言开发计划与验收 checklist

日期：2026-10-07。状态：首期开发交付完成，三端正式发布验收未齐（范围见实施结果）。设计依据：[UI 多语言模块设计](UI-I18N-DESIGN-20261007.md)。

首期交付 Auto、简体中文、English，默认 Auto 检测系统语言。支持完整 UI 即时切换、偏好保存、英文回退，以及后续扩展语言的资源和检查机制。完成标准包含页面、动态提示、后台错误、原生菜单和可访问名称，不能以“主要按钮已经翻译”代替完成。

checkbox 按实际实现与验证证据更新。尚未执行的原生/发布验收保持未勾；后续增加语言的条目是扩展流程，不代表首期欠项。

## 一 实施顺序与依赖

```text
P0 文案及状态盘点
        ↓
P1 语言核心与资源检查
        ↓
P2 Auto 与偏好 ──→ P3 稳定 ID 和语义状态
                            ↓
                   P4 后台错误契约
                            ↓
                   P5 全界面迁移与菜单
                            ↓
                   P6 原生验证与性能
                            ↓
                   P7 安装包发布和维护流程
```

建议拆成可审查的小批次，每批先保证中文现有流程可用，再接入英文，不进行一次性搜索替换。P1–P4 的内部基础允许逐步合入，但对用户开放英文前必须完成 P5 的全链路迁移，避免英文界面夹杂大量中文错误。

| 阶段 | 主要产物 | 阶段退出条件 |
|---|---|---|
| P0 | 文案清单、术语表、稳定 ID 清单 | 可展示内容有归属，状态比较点和错误来源已定位 |
| P1 | `neonmix-i18n`、双语资源、schema、检查器 | 候选匹配、资源、参数、回退与嵌入构建测试通过 |
| P2 | Auto 设置、偏好迁移与系统语言适配 | 默认自动识别，手选覆盖，保存失败可恢复 |
| P3 | 共用控件 ID、语义 Lane/事件/反馈 | 切换不丢草稿、焦点、计时或制造状态事件 |
| P4 | 结构化错误及兼容处理 | 两种语言正确呈现产品错误，兼容矩阵通过 |
| P5 | 全页面、托盘、菜单、AX 文案 | 首期所有自有 UI 文案完成，无未解释硬编码 |
| P6 | 三端原生报告、截图、回归及性能数据 | 各支持平台的功能、布局、输入、辅助功能门槛通过 |
| P7 | 完整包、变更说明、新语言贡献说明 | 安装升级验证、文档与实现同步、发布清单完整 |

## 三 P1 语言核心和资源检查

- [x] 新增 `crates/i18n` / `neonmix-i18n`，确认仅桌面和开发检查工具依赖，不进入媒体实时路径。
- [x] 核实 Fluent、语言标签解析、系统 locale 获取的版本和 feature，更新 Cargo.lock，记录新增依赖许可。
- [x] 建立语言 manifest：`zh-CN` 与 `en` 为 shipped，包含自称、方向和别名；Auto 作为偏好枚举而非资源语言。
- [x] 实现纯函数 LocaleResolver，区分用户偏好、候选列表、有效语言和回退原因。
- [x] 实现简体别名、英语地区回退、显式 script 优先及整个系统列表匹配，不在首个未知候选处停止。
- [x] 建立 `messages.toml` 参数 schema，生成 Rust Message 接口，不允许 UI 动态拼接 key。
- [x] 将 FTL 按功能域划分，完成公共动作、导航、偏好及基础错误的中英文资源。
- [x] 在构建期校验 FTL、必要属性和 schema，资源通过 `include_str!` 等方式嵌入二进制。
- [x] `build.rs` 对 manifest、schema 和所有资源声明准确的 `rerun-if-changed`，更改文案必须触发重建。
- [x] 实现“当前语言 → 英文 → 内置通用错误”的有界回退；格式错误不得引发产品 panic。
- [x] 以结构化原因收集缺键、缺参、格式错误，去重且不记录秘密或用户字符串参数。
- [x] 确认 Fluent 方向隔离在实际 egui 绘制中的行为，保留复制原始值的通路。
- [x] 加入资源解析/格式化缓存与 generation 失效机制，限制动态缓存大小。

**检查器要求**：拟新增 Rust `i18n-check` 工具，使用同一 FTL AST/parser 和 schema 检查逻辑；`tools/check_i18n.py` 只做项目编排，不另写一份简化语法解析器。

- [x] 检查重复 key、语法错误、缺失 shipped 消息/必要属性、未声明参数、参数契约错误及未知引用。
- [x] 检查 message/term 的传递依赖和引用循环，计算参数要求时不能只看当前消息第一层。
- [x] 使用类型化代表参数执行各消息及 selector 分支；覆盖语言实际需要的复数类别，不强求中英文分支相同。
- [x] 对允许函数建立白名单，未接入的 `NUMBER/DATETIME` 能力不得因 FTL 可解析就自动通过。
- [x] 对产品硬编码做 Rust 语法/调用点检查，中文和英文均覆盖；正则扫描只能辅助发现。
- [x] 例外须有文件位置、理由和类别，技术词、品牌、用户内容与测试 fixture 可明确豁免，不能豁免整个 UI 目录。
- [x] 检查器失败返回非零，并接入项目实际启用的验证入口。

**阶段验收**：删除一条英文资源、修改参数名、添加重复 key、引入循环引用均能稳定失败；未知运行期错误回退仍可读。破坏性样例使用临时 fixture，不能修改正式资源后忘记恢复。

- [x] ComboBox、折叠面板、ScrollArea、modal、卡片、胶囊、颜色动画和自绘节点检查显式 ID；重复对象用稳定对象 ID scope。

- [x] Lane 的角色、状态、网络状态使用语义类型；状态判定和 tone 仍来自业务数据。
- [x] RoomEvent 保存事件种类与参数，Marks 比较业务状态；切换语言不追加新的房间动态。

**阶段验收**：有未保存房间名/来源别名和待完成操作时切换，草稿、目标与最终动作一致；同一业务快照切换前后 `events::diff` 不产生额外事件。

## 六 P4 后台错误契约

- [x] 盘点并登记所有首期用户可见错误码，复用已存在机器码，不重新给同一含义发明多套编号。
- [x] Reply 增加可选 fault，ProcessStatus 增加对应结构化故障，参数使用闭合类型或经过 schema 验证的白名单。
- [x] 保留 legacy error，新增字段 `serde(default)`；对旧客户端读取新版回复做真实序列化/反序列化验证。
- [x] 将 backend 主动构造的中文错误逐步替换为“错误语义 + legacy 文本”，而不是让 UI 匹配完整中文句子。
- [x] CLI/Hub 返回已知机器码时保留结构到 UI，不经过字符串二次归类丢失原因。
- [x] 未知错误显示当前语言的通用说明，技术详情受限且可复制；不把任意 stderr 当主界面文案。
- [x] 参数解码拒绝未知/错类型字段，异常参数使用通用回退，不 panic。
- [x] 核对私钥、PIN、token、路径和设备身份的原有脱敏边界，fault 及错误日志不绕过导出白名单。
- [x] 与正在实施的 Windows 网络配置、密钥读取和正常退出错误保持同一语义映射。
- [x] 更新 DESKTOP-IPC-CONTRACT，记录保留 version 1 的验证结果，或确需变更时定义显式版本兼容行为。

| UI | 后台 | 必须验证 |
|---|---|---|
| 旧 | 旧 | 基线行为 |
| 新 | 新 | fault 优先，双语反馈完整 |
| 新 | 旧 | 已知机器码映射；未知文本通用回退；不要求 backend 按 UI locale 返回 |
| 旧 | 新 | 仍可读取 legacy error 和状态；新增字段不导致整体失败 |

**阶段验收**：端口占用、未配对、权限不足、revision 冲突、来源会话变化、worker 不可用、输出丢失、后台超时和偏好保存失败，均有中英文可操作反馈。

## 八 P6 测试与性能

### Auto 及偏好矩阵

| 输入/动作 | 预期结果 |
|---|---|
| 无文件或无 language 字段 | 偏好 Auto；按系统候选选择 |
| Auto + `zh-CN/zh-SG/zh-Hans` | 简体中文 |
| Auto + `en-US/en-GB` | 英文 |
| Auto + `[fr-FR, zh-CN, en]` | 简体中文 |
| Auto + `[zh-TW, en-GB]` | 英文，不把繁体自动当简体 |
| Auto + `[zh-Hant-CN]` | 英文回退，script 优先 |
| Auto + `[zh-Hans-HK]` | 简体中文，script 优先 |
| Auto + 空列表/无有效项 | 英文 |
| 手选 English + 中文系统 | 英文，重启仍英文 |
| 手选简体中文 + 英文系统 | 简体中文，重启仍中文 |
| 手选后改回 Auto | 立即按当前系统偏好重新解析 |
| Auto 下系统语言变化，重新激活 | 更新有效语言，持久值仍为 auto |
| 手选模式下系统语言变化 | 显示语言不变 |
| 检测临时失败 | 保持当前已解析语言，首次无结果才用英文 |
| 保存失败/偏好损坏/未知版本 | 不中断 UI；本次选择和未保存状态明确；不覆盖未知资料 |
| 连续修改动效和语言 | 两字段均正确保存，无相互覆盖 |

- [x] 上表均有确定性测试，明确区分检测返回空与检测异常。
- [ ] Windows 原生偏好列表、macOS 应用/系统语言、Linux locale 环境分别实测；不以 `chcp` 或时区代替 UI 语言。
- [ ] 中文 Windows 用户目录下完成偏好读写和 Auto 启动，与既有 Unicode 修复一起验收。
